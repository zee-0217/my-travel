# 전체 기능 재점검: 2026-11-24

접속 주소: http://localhost:3000

기존의 단위 테스트·모의 브라우저 검사만으로 실제 사용 상태를 보장하지 못한 부분을 보완했습니다. 이번에는 현재 실행 중인 localhost 서버에 실제 마우스 입력과 실제 OpenAI·NAVER 요청을 사용했습니다. 아직 데이터나 인증이 없는 기능은 정상 연결로 표시하지 않습니다.

## 발견한 문제와 조치

| 발견 | 확인 근거 | 조치 |
| --- | --- | --- |
| 지역 선택이 일반 드롭다운이 아님 | input+datalist이고 기본값 강릉에 따라 자동완성이 좁혀짐 | 전국 시·도·주요 도시를 포함한 34개 선택지의 select와 직접 입력 추가 |
| 실제 생성이 OpenAI에 연결되지 않음 | 제한된 실행 환경에서 Connection error → fetch failed → EACCES 재현 | 외부 통신이 허용된 환경으로 localhost 서버 재시작; 같은 서버로 실제 생성 성공 확인 |
| 연결 실패가 일반적인 AI 실패로만 표시됨 | 원인 구분 없이 AI_UNAVAILABLE 반환 | AI_CONNECTION_BLOCKED / AI_CONNECTION_ERROR로 분리하고 조치 안내 |
| 초기화 실패·입력 오류가 버튼 무반응처럼 보일 수 있음 | 모듈 실패/브라우저 기본 검증만으로 상태가 충분히 설명되지 않음 | 부트스트랩 실패 안내, 앱 준비 전 생성 잠금, 필드 오류 요약, 오류 발생 영역으로 이동 |
| 지역 변경 후 초기화 값 불일치 | hidden 지역값과 선택값의 reset 시점 차이; 회귀 검사에서 재현 | 선택·직접 입력·검색 지역·초기 샘플을 동기화하여 수정 |
| 직접 입력 중 도시명 접두어에서 선택기가 바뀔 수 있음 | 부산 → 부산 해운대 입력 경로 점검 | 자기 이벤트와 외부 값 변경을 구분해 연속 한글 입력 유지 |
| 생성 중 버튼 비활성 원인이 불분명할 수 있음 | 실제 검색·웹 검색·경로 조회가 수십 초~수분 걸릴 수 있음 | 진행 시간과 취소 안내 표시 |
| 기상청 키 미설정 | 서버 설정의 존재 여부만 확인, 값은 출력하지 않음 | 화면의 서비스 설정 상태에 연결 필요 표시 |
| 제주 날씨 지역명 표기 때문에 범위 검증 오류 가능 | 실제 제주 실행에서 날씨 범위 오류 1회 발견 | 제주/제주도/제주시 등 행정 표기 별칭 정규화와 도구 입력 지침 보강; 추가 실제 호출에서 NOT_CONFIGURED로 정상 분류 확인 |

프론트엔드 파일은 no-store로 제공해 오래된 HTML·모듈 혼용 가능성을 줄였습니다. 서비스 설정 상태는 인증값 존재 여부만 표시하고 실제 API 성공으로 오인하지 않도록 설명합니다.

모든 값이 확인된 완성 계획이라는 뜻은 아닙니다. 실제 생성에서는 부산 3일 계획에 확인된 방문 장소 4개와 숙소 2곳, 제주 2일 계획에 확인된 방문 장소 3개와 숙소 2곳이 연결됐습니다. 호출 한도·미제공 데이터로 남은 장소 유형·비용·일부 경로·영업시간·날씨는 확인 필요입니다.

## 연결 상태와 사용자 설정이 필요한 항목

| 서비스 | 실제 확인 | 필요한 조치 |
| --- | --- | --- |
| OpenAI Responses / Function Calling / web_search | 현재 서버에서 성공 | 현재 추가 키 설정 불필요 |
| NAVER API HUB 지역 검색 | 부산·제주에서 성공 | 현재 추가 설정 불필요 |
| 신규 Maps Directions 5 | 부산·제주에서 성공 | 현재 추가 설정 불필요 |
| 신규 Maps Web Dynamic Map | http://localhost:3000 실제 SDK·지도 표시 성공 | 다른 주소로 접속한다면 해당 주소도 NCP Web 서비스 URL에 등록 필요 |
| 기상청 단기예보 | 인증키 없음 | 아래 두 인증 방식 중 하나 신청·설정 후 서버 재시작 |
| 영업시간·실요금·객실 재고 | 자동 수집 연동 없음 | 공식 운영 정보/요금/재고 데이터 연결을 별도로 구현하거나 확인 자료 등록 필요 |

날씨는 [기상청 API허브](https://apihub.kma.go.kr/apiList.do?seqApi=10)의 KMA_API_KEY, 또는 [공공데이터포털 기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do)의 KMA_SERVICE_KEY를 .env에 설정합니다. 채팅에 인증키를 보내지 않습니다. 날짜가 실제 예보 범위에 포함될 때만 조회할 수 있으며 먼 미래는 키가 있어도 미확인입니다.

[NAVER 지역 검색 공식 응답](https://api.ncloud-docs.com/docs/naver-api-hub-search-local)에는 영업시간·숙박 요금·객실 재고가 없습니다. 이 서비스의 키를 다시 발급해도 해당 정보가 생기지 않습니다. 관광 소개 정보 확장에는 [한국관광공사 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do?recommendDataYn=Y) 등을 검토할 수 있지만 현재 앱의 연동은 구현되지 않았고, 숙박 실시간 요금/재고까지 보장하는 서비스는 아닙니다. 기존 서버 확인 자료의 연결 지점은 [일정 검증](ITINERARY_VALIDATION.md)과 [숙소 추천](LODGINGS.md)에 설명했습니다.

## 재현 가능한 검사

```powershell
npm.cmd test              # 98개: 실제 외부 API 사용 없음
npm.cmd run check         # JavaScript 문법
npm.cmd run audit:controls # 실제 브라우저 지역·직접입력·초기화·실패 안내, AI 요청 없음
npm.cmd run audit:services # 현재 localhost 서버를 통한 실제 NAVER 요청, 계산/날씨 검사
npm.cmd run audit:live     # 현재 localhost 화면에서 실제 OpenAI·NAVER 사용
```

audit:services와 audit:live는 실제 API 사용량을 발생시킵니다. 서버는 먼저 npm.cmd run dev로 실행합니다. 이번에 발견한 것처럼 서버 실행 환경이 외부 네트워크를 차단하면 키가 설정돼 있어도 동작하지 않습니다. 테스트 클라이언트만 외부 통신이 가능한 것으로는 충분하지 않습니다.

실행 보고서와 실제 계획은 Git에서 제외한 .local-preview/에 저장했습니다: full-browser-audit.json, services-audit.json, weather-agent-audit.json, audit-busan.json, audit-jeju.json. 실제 생성 검사와 모의 데이터 검사를 구분합니다.

현재 실행한 localhost 서버는 외부 통신이 가능한 환경으로 재시작했습니다. 화면을 Ctrl+Shift+R로 새로고침하고 새 계획을 생성해 확인할 수 있습니다. 서버 재시작으로 이전 수정 세션은 만료될 수 있습니다.
