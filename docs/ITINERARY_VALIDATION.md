# 일정 검증과 자동 재계획

`POST /api/plan`은 도구 결과에 연결된 초안을 `validateItinerary()`로 검사합니다. 계산은 JavaScript에서 수행하고, 문제가 있을 때 LLM에 검증 결과와 초안을 돌려보냅니다. 모델은 기존 근거를 재사용하거나 필요한 도구만 다시 선택해 장소·방문 시각을 수정합니다. 고정된 도구 실행 순서는 없습니다.

## 검사 기준

| 검사 | 판정 근거 | 정보가 부족할 때 |
| --- | --- | --- |
| 예산 초과 | 실제 예산 도구의 금액이 있는 항목 합계와 총예산 비교 | 최종 합계는 확인 필요; 이미 부분 합계가 초과하면 경고 유지 |
| 방문 장소 수 | 날짜별 장소 배열 길이와 maxPlacesPerDay 비교 | 기본 최대 4곳 |
| 자동차 이동시간 | 일치하는 장소 좌표의 Directions 5 durationMs와 구간·하루 제한 비교 | 미조회 구간은 확인 필요, 0분으로 합산해 충족이라고 말하지 않음 |
| 일정 중복 | 계획상 time~endTime의 모든 쌍 비교, 실제 이동까지 다음 시작 전에 가능한지 계산 | 종료 시각이 없어도 같은 시작 시각·확실한 중복은 검출; 나머지는 확인 필요 |
| 영업시간 충돌 | 방문일에 적용되는 출처가 확인된 영업 구간 안에 방문 전체가 포함되는지 비교 | 확인 필요; 운영 중이라고 추정하지 않음 |
| 날씨 적합성 | 실제 강수 예보와 장소의 실외 유형, 방문 시간대 비교 | 날씨·유형·시간대 결측은 확인 필요 |

이동 제한을 입력하지 않으면 긴 이동을 점검하는 기본 기준은 **구간 60분, 하루 합계 180분**입니다. 사용자 입력이 있으면 그 값을 우선합니다. 이동은 일정의 인접 방문지 사이만 포함하며 출발지/귀가/숙소 경로가 따로 조회되지 않았다면 포함하지 않습니다.

방문 종료 시각 `endTime`은 LLM의 **계획 제안**입니다. 실제 체류 시간이나 영업시간이 아닙니다. 같은 날의 HH:mm을 지원하며 자정을 넘기는 체류는 오류로 표시하고 날짜별로 다시 배치하도록 요청합니다. 종료와 다음 시작이 같은 시각이면 방문 구간 자체는 겹치지 않지만 자동차 이동시간이 있으면 충돌할 수 있습니다.

날씨는 비·눈 또는 강수확률 60% 이상인 실외 방문을 주의 항목으로 봅니다. 제공된 시간대가 모두 건조하면 다른 시간대의 비 때문에 그 방문을 충돌로 보지 않습니다. 3시간 간격의 예보 사이 빈 시간을 채우지 않습니다. 카테고리의 해변·해수욕장·계곡·수목원·도시공원은 실외 계획으로 보수적으로 분류하고 근거를 명시합니다. 박물관이라는 이름만으로 건물 전체의 실내 여부를 보장하지 않습니다.

## 확인된 영업시간의 경계

현재 NAVER 지역 검색은 영업시간을 제공하지 않습니다. LLM의 주장, URL 한 개, 웹 검색을 했다는 사실만으로 영업시간을 확인된 정보로 승격하지 않습니다. 따라서 기본 앱에서 영업시간은 대부분 **확인 필요**입니다. 이번 변경은 영업시간 자동 수집기를 추가하지 않습니다.

공식 안내에서 확인한 구조화된 자료는 서버의 `src/services/place-facts.js`에 등록하거나 서버 의존성 `getPlaceFacts(place, date)`로 주입할 수 있습니다. 이름·주소·적용 날짜가 일치하는 자료만 연결합니다. 예시 형식(아래 장소·시간은 테스트 예시이며 실제 운영정보가 아님):

```js
{
  name: '테스트 장소',
  address: '테스트 주소', // place.roadAddress || place.address와 정확히 일치
  date: '2026-11-24',
  openingHours: {
    status: 'confirmed',
    date: '2026-11-24',
    sourceUrl: 'https://example.com/official',
    checkedAt: '2026-11-24T00:00:00Z',
    intervals: [{ open: '09:00', close: '12:00' }, { open: '13:00', close: '18:00' }]
  },
  environment: { type: 'indoor', basis: '공식 시설 안내에서 확인' }
}
```

intervals=[]는 확인된 휴무입니다. 방문 날짜가 다르거나 출처/확인 시각이 없으면 확인 필요입니다. 휴게시간을 사이에 둔 복수 구간을 지원하며 방문 전체가 하나의 구간 안에 들어가야 합니다. 자정을 넘는 영업 구간은 날짜별로 나누어 등록해야 합니다. HTTP 입력과 모델 출력에는 영업시간·환경 근거 필드를 허용하지 않습니다. 출처 확인과 자료 갱신은 서버 자료 제공자의 책임이며 자동 진위 확인은 아닙니다.

## 횟수와 종료

`.env`의 `AGENT_MAX_REPLANS=2`로 기본 최대 2회 수정합니다(0~4). `.env.example`에 항목을 추가했으며 기존 `.env` 값을 덮어쓰지 않습니다. 별도 지정 없이도 기본값이 적용됩니다. 전체 `AGENT_MAX_ITERATIONS`, `AGENT_MAX_TOOL_CALLS`, `AGENT_TIMEOUT_MS` 한도가 우선합니다. 새 패키지나 인증키는 필요하지 않습니다.

가격·영업시간·날씨 등이 미확인인 것만으로 반복 재계획하지 않습니다. 계산된 초과·충돌 및 날씨 주의 항목이 있을 때만 다시 요청합니다. 한도에 도달하면 남은 문제와 확인 필요를 그대로 반환합니다. 수정 중 API 오류가 나면 마지막 검증 초안과 안전한 오류 상태를 표시하고, 사용자가 취소하거나 전체 시간이 초과하면 기존 취소/오류 처리를 유지합니다.

## 결과와 화면

`plan.validation`은 다음을 제공합니다.

- `status`: passed / needs_confirmation / problems_found
- `issues`: code, severity(error/warning/unknown), actionable, dayIndex, stopIndex, message와 계산 근거
- `replanCount`, `maxReplans`, `stopReason`: 실제 시도 횟수와 종료 사유
- `history`: 최초 및 수정 초안별 JavaScript 검사 결과
- `repairs`: 이전 문제(수정 이유), 서버가 비교한 실제 장소·시각·방문 수 변경, 모델의 수정 설명

화면의 **일정 검증 · 자동 재계획**에서 남은 문제와 수정 이유를 표시합니다. 이전 문제와 확인 필요 목록은 펼쳐 볼 수 있습니다. 장소나 시간이 바뀌지 않았으면 변경을 확인하지 못했다고 표시하며, 미확인으로 바뀐 사실을 해결 완료라고 보장하지 않습니다. 실제 도구 호출만 Agent Trace에 남기며 JavaScript 검사를 가짜 Tool 호출로 추가하지 않습니다. JSON 다운로드에도 검증 기록이 포함됩니다.

검증 시마다 기존 검색·날씨 결과는 보존하지만, 경로는 수정된 이웃 장소의 좌표와 정확히 일치할 때만 연결합니다. 가격의 근거가 없는 현재 앱은 합계와 예산 충족 여부를 계속 미확인으로 유지합니다.

## 실행과 확인

```powershell
npm.cmd run test:validation
npm.cmd test
npm.cmd run check
```

자동 테스트는 계산 경계, 미확인 처리, 비 예보·실외 장소, 날짜별 영업시간, 선택적 도구 재호출, 수정·실패·한도·SDK/HTTP 흐름을 모의 데이터로 검증합니다. 실제 OpenAI 검사는 의도적으로 겹치게 만든 테스트 초안을 전달했고 한 번의 실제 Responses 요청으로 장소 수·시각을 수정했습니다. 해당 검사에서는 실제 날씨·가격·영업시간을 확인했다고 취급하지 않았습니다.
