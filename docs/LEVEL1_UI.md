# 여행 결과 화면과 신규 지도

기존 입력 폼·지역 검색·수동 경로·Agent·다운로드 기능과 크림/초록색 디자인을 유지합니다.

## 결과 보기

- 날짜 탭으로 일정·마커·경로를 함께 전환합니다. 방향키·Home·End도 지원합니다.
- 방문 시각, 장소명, 추천 이유, 체류 제안, 주소, 실제 검색 출처와 이동 시간을 표시합니다.
- 출처는 실제 NAVER API HUB 검색 결과와 검색어입니다. 제공된 업체 URL만 링크로 표시하며 검색되지 않은 장소는 Agent 제안으로 구분합니다.
- 비용 표에서 항목·금액·확인 상태와 총예산·예상 비용 합계·잔여 예산을 비교합니다. 미확인 가격을 0원으로 계산하지 않습니다.
- Agent Trace는 실제 도구 이름·결과 요약·완료·확인 불가·오류 상태와 실제 웹 출처를 제공합니다.

## Web Dynamic Map 설정

신규 SDK `https://oapi.map.naver.com/openapi/v3/maps.js?ncpKeyId=...`를 사용합니다. [공식 신규 SDK 안내](https://navermaps.github.io/maps.js.ncp/docs/tutorial-2-Getting-Started.html)

`GET /api/maps/config`는 SDK의 공개 Client ID만 제공합니다. Client Secret, OpenAI 키, API HUB 인증 정보는 반환하지 않습니다. Client ID는 SDK 인증 특성상 브라우저에서 볼 수 있으며 NCP의 Web 서비스 URL 제한으로 출처를 관리합니다.

NCP Maps Application에서 **Web Dynamic Map**을 활성화하고 사용하는 주소를 **Web 서비스 URL**에 등록하세요(예: `http://localhost:3000`, `http://127.0.0.1:3000`). 경로 REST 요청에는 **Directions 5**도 활성화합니다. 기존 `.env`의 Maps 인증 정보를 그대로 사용합니다.

인증 실패·설정 누락·SDK 로딩 지연은 지도 카드에서 안내합니다. 일정·예산·Trace는 계속 사용할 수 있습니다.

## 실제 좌표와 경로

`public/js/trip-map.js`가 확인된 장소의 WGS84 소수 경위도를 SDK `LatLng(위도, 경도)`에 전달합니다. 원본 정수 mapx/mapy나 임의 마커 위치를 사용하지 않습니다.

Directions 5의 `path`는 `[경도, 위도]` 배열입니다. 서버는 실제 선형을 보존하지만 LLM에는 거리·시간과 점 개수만 전달해 컨텍스트 크기를 제한합니다. 실제 선형은 최종 화면 응답에 포함합니다. [공식 경로 응답 문서](https://api.ncloud-docs.com/docs/application-maps-directions5)

선택한 날짜의 인접 장소와 출발·도착 좌표가 일치하는 성공 경로만 Polyline으로 표시합니다. 선형이 없거나 잘못되면 직선을 만들지 않습니다. 날짜를 바꾸면 이전 마커와 선형은 제거합니다.

도구 응답 본문에 `callId`를 명시해 모델이 결과를 참조할 수 있게 했습니다. 참조가 빠졌을 때는 장소명이 유일하게 정확히 일치할 때만 복원하며 동명 장소를 임의 매칭하지 않습니다.

Agent의 마지막 반복에서는 추가 도구 호출을 닫고 확보된 근거만으로 일정을 마무리합니다. 부족한 가격·경로는 미확인으로 남깁니다.

## 검사

`npm.cmd run check`, `npm.cmd test`로 공개 SDK 설정·좌표/선형·직선 대체 금지·참조 ID·유일 장소 복원·마지막 반복 마무리와 기존 기능을 검사합니다. 실제 부산·제주 요청 및 브라우저 결과도 별도로 검증합니다.

2026-11-23 부산과 제주도 1박 2일·2인·총예산 70만원 요청을 실제 브라우저 폼으로 실행했습니다. 초기에 반복 제한과 참조 ID 누락 문제를 발견해 보완한 후, 두 요청에서 각각 실제 검색 장소 8곳이 연결된 최종 일정을 확인했습니다.

지도 리소스 정책과 SDK 비동기 초기화를 수정한 뒤에는 **저장한 실제 Agent 응답을 재사용**해 추가 OpenAI 비용 없이 지도 UI를 재검증했습니다. 실제 NAVER SDK와 지도 타일은 네트워크에서 로드했습니다.

| 확인 항목 | 부산 | 제주도 |
| --- | --- | --- |
| 날짜 탭 | 2일 전환 | 2일 전환 |
| 실제 검색 장소 연결 | 총 8곳 | 총 8곳 |
| 첫날 지도 마커 | 4개 | 4개 |
| 실제 자동차 경로 표시 | 조회된 경로 1개 | Agent가 미조회하여 선 없음 |
| 비용과 잔여 예산 | 가격 근거가 없어 미확인 | 가격 근거가 없어 미확인 |
| 출처·실제 Tool Trace·예산 표 | 확인 | 확인 |
| 데스크톱 1440px·모바일 390px | 가로 넘침 없음 | 가로 넘침 없음 |

두 지도에서 실제 타일 로딩을 확인했고 브라우저의 런타임·CSP 오류가 없었습니다. 기존 검색·수동 경로·초기화·다운로드·오류/취소 기능도 별도 브라우저 회귀 검사로 확인했습니다.
