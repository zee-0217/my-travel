# Level 2: 날씨와 여행 속도를 고려하는 Agent

Level 1의 장소 검색, 자동차 경로, 예산, 지도, 날짜 탭, 취소·재시도·다운로드를 유지합니다. 새 패키지는 필요하지 않습니다.

## 인증 설정

기존 `.env`의 다른 인증 값은 보존하고 아래 중 **한 가지**만 입력한 뒤 서버를 재시작합니다. `.env.example`에는 빈 항목만 공유합니다.

```dotenv
# 기상청 API허브 단기예보 활용 신청 후 발급된 authKey
KMA_API_KEY=
# 또는 공공데이터포털 기상청 단기예보 조회서비스의 디코딩 인증키
KMA_SERVICE_KEY=
```

두 값이 있으면 KMA_API_KEY를 우선합니다. 키가 없으면 `NOT_CONFIGURED`/날씨 미확인으로 처리하고 일정 생성은 계속할 수 있습니다. 키를 브라우저나 채팅에 입력하지 않습니다. 기상청 키는 OpenAI에도 전달하지 않습니다.

## 공식 예보와 날짜

- [기상청 API허브 동네예보 문서](https://apihub.kma.go.kr/apiList.do?seqApi=10)의 `VilageFcstInfoService_2.0/getVilageFcst` JSON API를 사용합니다.
- API허브: `https://apihub.kma.go.kr/api/typ02/openApi/VilageFcstInfoService_2.0/getVilageFcst`, 쿼리 인증 `authKey`.
- 공공데이터포털 대안: `https://apis.data.go.kr/1360000/VilageFcstInfoService_2.0/getVilageFcst`, 쿼리 인증 `serviceKey`. 인코딩 키도 중복 인코딩되지 않게 한 번 해제합니다.
- 한국 시간의 발표 시각(02·05·08·11·14·17·20·23시)을 사용하고 게시 지연에 대비해 15분 여유를 둡니다. 요청은 페이지당 1,000행, 최대 4,000행, 페이지별 12초 제한입니다. 성공 응답을 격자·발표시각별로 10분간 메모리에 캐시합니다.
- [기상청 단기예보 기간 안내](https://data.kma.go.kr/data/rmt/rmtList.do?code=420&pgmNo=572)에 따르면 현재 예보기간은 오늘을 포함해 최대 5일이며 발표 시각에 따라 더 짧을 수 있습니다. 과거와 오늘+5일 이후는 네트워크 요청 없이 미확인으로 반환합니다. 범위 안이어도 실제 응답에 해당 날짜가 없으면 `NO_FORECAST_FOR_DATE`입니다. 중기예보·기후 평균으로 채우지 않습니다.
- `TMP`(기온), `POP`(강수확률), `PTY`(강수형태), `SKY`만 실제 제공값을 추출합니다. 결측은 null입니다. 화면의 기온 범위는 **제공된 예보 시간대의 범위**이며 일 최저·최고 기온을 보장하지 않습니다.
- `PTY` 1·2·4가 있으면 비 예보, 3은 눈입니다. 비·눈 또는 제공 시간대 최대 POP 60% 이상이면 `indoorSuggested:true`입니다. 60%는 앱의 일정 조정 기준이며 기상청 경보 기준이 아닙니다.

## 지역과 좌표

`get_weather({region, date, location})`의 location은 WGS84 십진 경위도 또는 null입니다. 기상청 5km Lambert 격자로 변환합니다. Agent가 좌표를 전달하려면 현재 요청의 NAVER 검색에서 확인된 좌표여야 합니다. 날짜는 여행 기간, 지역은 사용자의 입력 범위로 제한합니다.

location=null이면 서울·부산·제주시·서귀포·강릉·속초·경주·전주·여수·인천·대전·대구·광주·울산·세종·수원·춘천·청주·포항·목포의 대표 지점을 지원합니다. 제주도는 제주시 대표 지점이며 섬 전체의 예보가 아닙니다. 미등록/모호한 지역은 `LOCATION_UNKNOWN`; 필요한 경우 Agent가 장소를 검색해 확인된 좌표로 다시 조회할 수 있습니다. 화면에는 조회 지점과 발표 시각, 기상청 출처를 표시합니다.

## 선택적 도구 호출과 일정 변경

OpenAI Responses API의 `tool_choice:auto`를 유지합니다. 날씨·실내 대안이 필요할 때만 모델이 `get_weather`와 `search_places`를 선택합니다. 비 예보 결과가 모델에 전달되면 취향에 맞는 박물관·전시관·카페 등으로 교체하거나 순서를 조정할 수 있습니다. 이미 적절한 검색 결과가 있으면 재사용합니다. 도구가 없거나 오류가 나면 실패를 Trace에 남기고 날씨를 미확인으로 유지합니다. 다른 도구를 강제 실행하지 않습니다.

예: “부산에서 자연과 카페를 즐기고 싶어요. 비가 오면 실내 전시로 바꿔 주세요.” 모델 판단에 따라 날씨 조회 → 실내 검색 → 필요 경로 조회 → 최종 일정이 가능하며 항상 같은 순서로 실행되는 것은 아닙니다. 날씨 미조회는 `NOT_REQUESTED`이며 맑음으로 취급하지 않습니다.

## 방문 수와 이동 제한

`POST /api/plan`에 다음 필드를 추가합니다. 기존 요청도 기본값으로 동작합니다.

| 필드 | 기본값 | 유효 범위 |
| --- | --- | --- |
| maxPlacesPerDay | 4 | 1~6곳 |
| maxTravelMinutesPerLeg | null(미지정) | 5~180분 |
| maxTravelMinutesPerDay | null(미지정) | 5~600분 |

LLM에 사용자 취향과 제한을 전달하고 방문 수 상한은 JavaScript 검증 후 자동 재계획에 반영합니다. JSON 스키마는 비정상적인 응답 크기를 막기 위해 날짜당 12곳의 절대 상한을 둡니다. 경로 결과에 구간 제한 초과 여부를 함께 전달하므로 모델이 장소를 바꿀 수 있습니다. 최종 날짜별 `travelConstraints`는 **인접 방문지 사이**의 실제 자동차 경로만 합산합니다. 출발지에서 여행 지역까지, 귀가, 숙소 왕복은 명시적으로 일정에 넣고 조회하지 않으면 포함되지 않습니다. 확인되지 않은 구간이 있으면 충족 여부는 미확인, 확인된 값만으로 이미 초과하면 초과 경고를 표시합니다. 최종 결과가 항상 제한을 만족한다고 보장하지 않으며 미완료 검증을 숨기지 않습니다. ## 독립 실행과 테스트

```powershell
npm.cmd run test:weather
npm.cmd run test:weather:live -- 부산 2026-11-24
npm.cmd run test:weather:live -- 제주도 2027-01-01
npm.cmd test
npm.cmd run check
```

날짜는 실행 시점에 맞춰 변경하세요. `test:weather:live`는 실제 함수를 실행하며 키가 없거나 범위 밖이면 실제 예보를 확인했다고 표시하지 않습니다. 직접 HTTP로 테스트하려면 `POST /api/weather`에 `{"region":"부산","date":"2026-11-24","location":null}`을 전달합니다. 응답은 `{weather: ...}`입니다.

자동 테스트는 공식 응답 형식의 **모의 데이터**로 좌표, 날짜 범위, 강수 판단, 캐시, 오류·키 비노출을 검증합니다. Agent 테스트는 모의 LLM/도구 응답으로 선택 호출, 비 예보 후 실내 검색, 이동 제한, 실패 후 계속 진행을 검증합니다. 기상청 인증키 설정 후 실제 예보 응답을 추가로 확인해야 합니다.

구현 시 전체 자동 테스트 61개와 Chrome의 기존 기능·Level 2 입력/날씨 표시·모바일 검사를 통과했습니다. 실제 OpenAI·NAVER 통합 검사에서는 **모의 비 예보**를 주입했고 모델이 `get_weather`, `search_places`, `web_search`만 선택해 부산박물관 실내 일정을 제안했습니다. 이것은 실제 기상청 예보 검증 결과가 아닙니다. 독립 실제 함수 실행으로 키 미설정(`NOT_CONFIGURED`)과 먼 미래(`OUTSIDE_FORECAST_RANGE`)의 미확인 처리를 확인했습니다.
