# 브라우저 일정 저장

1. AI 여행 계획을 생성한 뒤 결과 위의 **여행 일정 저장**을 누릅니다. 샘플 미리보기는 저장하지 않습니다.
2. **저장한 여행** 목록에서 **일정 열기**를 누르면 기존 날짜별 일정·지도·예산·검증·Agent Trace 화면에 표시됩니다. 위 여행 입력 조건도 함께 복원됩니다.
3. **직접 수정**에서 제목, 여행 메모, 방문·종료 시각, 장소별 메모를 고칩니다. **수정하고 저장**하면 기존 순수 JavaScript 검증 함수를 다시 실행합니다. 시간 충돌 등은 기존 검증 화면에 표시하며, AI 재계획이나 API 재조회는 자동 실행하지 않습니다. 장소와 확인된 좌표·출처는 유지합니다.
4. 열린 저장 일정을 바꾼 뒤 **변경사항 저장**을 누르면 같은 저장 항목을 갱신합니다. **새 사본으로 저장**은 별도 항목을 만듭니다. AI 채팅 수정 결과는 저장 버튼을 눌러 반영합니다.
5. 목록의 **삭제**는 해당 저장 항목만 지웁니다. 현재 화면의 일정은 유지됩니다. **JSON 내보내기**와 기존 **일정 다운로드**로 파일을 보관할 수 있습니다.

## 데이터 범위

- `localStorage` 키: `travel-piece.saved-trips.v1`. 버전 1 형식이며 최대 30개, 직렬화 크기에 보수적인 4MiB 한도를 적용합니다. 브라우저별 실제 저장 한도로 먼저 실패할 수 있으며 실패 시 기존 저장 데이터는 변경하지 않습니다.
- 별도 DB나 회원가입은 필요하지 않습니다. 같은 브라우저·같은 origin에서만 목록을 공유합니다. `localhost:3000`과 `127.0.0.1:3000`은 서로 다른 저장소입니다. 시크릿 모드 종료나 브라우저 데이터 삭제 시 사라질 수 있습니다.
- 여행 조건·날짜별 일정·지도 좌표·실제 조회 경로·예산·확인된 공개정보·검증·Trace 요약을 저장합니다. API 키, 인증 헤더, 비밀 설정, 서버 도구 실행 컨텍스트와 수정 세션 ID는 저장하지 않습니다. JSON 내보내기도 같은 필터를 적용하며 인증 정보가 든 URL은 정리합니다. 여행 메모에는 개인 비밀을 입력하지 마세요.
- JSON 파일은 기존 다운로드처럼 `title`, `days` 등 여행 계획 필드를 최상위에 보관합니다. 파일 가져오기는 이번 범위에 포함하지 않습니다.
- 저장된 예보·가격·경로는 저장 시점의 자료입니다. 다시 열기만으로 최신 정보를 조회하지 않으며 출발 전 확인이 필요합니다.

## AI 수정 세션

서버는 기존처럼 수정 컨텍스트를 메모리에 30분간 보관합니다. 같은 페이지에서 저장 후 다시 연 일정은 가능한 경우 기존 AI 채팅 수정을 이어갑니다. 새로고침·서버 재시작·세션 만료 이후에도 로컬 일정 열기와 직접 수정은 가능합니다. AI로 장소 변경을 요청하려면 복원된 여행 조건으로 새 일정을 생성하세요. 브라우저에 보관한 내용을 서버 검증 근거로 승격하지 않습니다.

## 검증

```powershell
npm.cmd run test:saved
npm.cmd run audit:saved
```

브라우저 검사는 실제 Chrome의 localStorage와 JSON 내보내기를 사용하며 AI 응답은 모의 데이터입니다. 키나 유료 AI 호출이 필요하지 않습니다.
